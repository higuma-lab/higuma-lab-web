- このサイトは、AI コーディングエージェントの Claude Code と一緒に作りました。文章で頼むと、プログラムを書き、動作の確認までしてくれる AI です。
- デザインやコードはほぼ任せ、私は「作る順番」「確認のタイミング」「作業の分担」を決めました。
- 「Web サイトを自分でも作れるのか」と気になっている人に向けて、進め方をまとめます。

## きっかけ

AI を使えば Web サイトを作れる、という発信を SNS でよく見かけます。技術者ではない人が AI で Web サイトを作るのを手伝うことを、事業の一つにできないかと考えていました。ちょうど開発中のアプリを紹介する場所も必要だったので、事業のサイトを作ることにしました。

これからは誰もが AI を使うようになると思います。自分も一度、経験しておこうと考えました。

## 何を作ったか

サービスの紹介、制作物、プロフィール、お問い合わせ、自作アプリのプライバシーポリシー（日本語・英語）を載せたサイトです。10 月 5 日から 9 日までの 5 日間で、設計・実装・テストから、公開に使う設定（AWS の構築手順）、運用の手順書までを作りました。

使っている主な道具は次のとおりです。名前は覚えなくて大丈夫です。

- **Astro**：ページをあらかじめ作っておく「静的サイト」の道具。ページが軽く（1 ページ 5〜13KB）、動く部分（JavaScript）はスマートフォンのメニューの開閉だけです。
- **AWS（Amazon のクラウド）**：サイトを置いて配信する場所。費用は月 100 円前後と見積もっています。ほとんどが DNS（ドメインの住所録）の料金で、ほかは無料の範囲に収まる見込みです（ドメインの更新料とメールの月額は別）。
- **GitHub**：プログラムの保管サービス。変更を送るたびに、自動で点検が走るようにしています。点検に通った変更を自動で公開する仕組みも用意しました（公開のほうは、AWS の準備ができてから動き始めます）。

## AI との分担

載せる内容のアイデアは ChatGPT（別の会社の対話型 AI）と相談してまとめ、形にする段取りと点検を Claude Code に指示しました。

デザインはほとんど指定していません。配色は、ロゴとマスコットの画像から色を拾って決めてくれました。マスコットの茶色は、白い背景の上の文字にすると読みにくい（明るさの差がわずかに足りない）と計算で分かり、飾りだけに使い、文字には濃い茶色を別に用意しています。

自分で指定・判断したのは次のようなことです。

- **ロゴ**：ChatGPT で作ったロゴを Claude Code に渡すと、直すべき点を挙げて描き直してくれました。最初の清書は「H」が「U」に見えたので直してもらい、次の版は好みではなかったので「可愛くない」と伝えて、やり直してもらいました。3 案を並べて比べ、輪郭を横長にして目を離した案に決めました。決めたあとは、ロゴの図形がすでに登録されている商標に似ていないかを、特許庁のデータベース（J-PlatPat）で自分で調べ、似たものは見つかりませんでした（調べたのは図形だけです）。
- **公開する時期**：実績として示せるのが、このサイトと公開予定のアプリだけの段階でした。これで公開しても効果が薄いのではないか、もっと何か作ってからの方がよいかを Claude Code に相談し、アプリの公開に合わせて、待たずに公開することにしました。そのかわり、実績のページは「制作物・取り組み」とし、「自社プロダクト」「お客様案件」などの種別を付けています。お客様の案件がまだないことも、そのまま分かるようにするためです。
- **役割分担**：作る役と、点検だけを担当する役（原稿・サイトの品質・インフラの安全性の3つ）に分けました。小さなサイトで作る役を分けると、見た目や書き方の統一感が崩れやすいため、作る役は1つにしています。

## 気をつけたこと

- **確認のタイミングを先に決める**：作業を 9 つの段階に分け、設計・デザイン・テスト・AWS の設定の 4 つの節目では、必ず作業を止めて私が確認してから次に進むようにしました。節目ごとに、そのときできている画面や結果を見て、気づいたことを伝えています。
- **ルールを文書にする**：長い会話になると、最初の指示が薄れる恐れがあります。そこで、守ってほしいことを文書にまとめ、Claude Code が毎回読む形にしました。たとえば「架空の実績を作らない」「決まっていない情報は TODO と書き、画面にも仮の内容だと分かる目印を出す」「パスワードなどの秘密の情報をプログラムの保管場所に入れない」といったルールです。
- **本番の環境には触らせない**：AWS のアカウントやドメインの設定など、実際の環境での作業は AI にさせないルールにし、手順書を書いてもらって自分で行う形にしました。ドメイン、メール、AWS のように自分の名前での契約が必要なものも、自分で申し込みます。
- **公開してよい情報だけを残す**：プログラムは後で公開する予定のため、変更の記録に残るメールアドレスを、最初の記録の前に GitHub の公開用のアドレスにしました。
- **決めたことを理由と一緒に残す**：決めたことに番号を付けて、理由と一緒に記録してもらいました。後から「なぜこうしたのか」をたどれます。

## 途中で見つかったこと

点検役の AI は、作る役の AI が見落としていたことをいくつも見つけました。

- URL の処理の中にあった「別のサイトへ飛ばせてしまう抜け穴」
- まだ決まっていない仮の文面が、画面上は確定した内容に見えること
- 数値に、測った条件が書かれていないこと

ほかにも、思わぬところでつまずきました。

- **日本語の文の途中に、余分な空白が入る**：プログラムの見た目を整える道具が、日本語の文を途中で改行していました。ブラウザは改行を空白として表示するため、「、 以下」のような空白が入っていました。文章の多いページは書き方を変えて直しました。
- **自分の PC では起きない不備**：Windows で作った設定ファイルに、別の OS（Linux）で動かすための記載が抜けていて、GitHub の自動の点検で初めて失敗しました。点検の仕組みがあったので、公開前に気づけました。

全ページについて、横スクロールが出ないこと、リンク切れがないこと、アクセシビリティ（障害のある方も使いやすいか）の自動チェックで違反がないことを、変更のたびに自動で確かめています。10 月 9 日の時点では、いずれも 0 件でした（読み上げソフトでの実際の確認はこれからです）。

## やってみて

Web サイトづくりの予備知識がほとんどない状態から、この速さで作れたのは AI の助けがあったからです。

ただ、何を作るか、どこで確認するか、どこまで任せるかは人が決める必要がありました。実際の画面を見ながら気づいたことを伝えられたので、早い段階で直せました。

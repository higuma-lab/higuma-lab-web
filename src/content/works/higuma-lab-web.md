## 課題

事業の紹介、制作物の掲載、お問い合わせの窓口に加えて、Windows アプリ「NoteFlip」のプライバシーポリシーとサポートページ（日英）を置く場所が必要でした。サーバーの処理が要らない内容のため静的サイトにし、記事や制作物は Markdown で書き足すだけで更新できるようにしました。

## 設計

- 静的サイトとして生成し、サーバーの処理を持たない構成にしました。お問い合わせはメールのリンクだけにしています。
- サービス・制作物・ブログはリポジトリ内の Markdown と YAML で管理し、ビルド時に項目の不足や型の誤りを検出します。
- 制作物には「自社プロダクト」「サンプル制作」「技術検証」「お客様案件」の種別ラベルを付け、取り組みの種類が分かるようにしました。
- 決めたことは理由と一緒に決定ログとして残し、作業はフェーズごとに区切って、区切りごとに内容を確認してから次に進めました。

## 技術

（ここからは開発者向けの内容です。）

- **サイト**：Astro 7 ＋ TypeScript（strict）。クライアント側の JavaScript はスマートフォンのメニューの開閉だけです。Web フォントは使わず、CSS は1ファイルにまとめています。
- **配信**：Amazon S3（非公開）を CloudFront から OAC で読み、DNS は Route 53、証明書は ACM です。www から apex への転送と、ディレクトリの URL の解決は CloudFront Functions で行っています。
- **インフラ**：AWS CDK（TypeScript）で4つのスタックに分け、DNS とメールのレコードは、サイトのスタックを消しても残るようにしています。
- **デプロイ**：GitHub Actions。PR で lint・型チェック・テスト・ビルド・リンク切れ・E2E を実行し、`main` へのマージで S3 に同期する構成です（AWS の環境は公開に向けて準備中）。AWS には OIDC で接続し、アクセスキーを持たせない設計です。
- **テスト**：Vitest（ユニット）、Playwright と axe（全ページの表示・アクセシビリティ・SEO のメタ情報）、内部リンクのリンク切れの確認。

## 工夫した点

- **AI との分担**：実装は役割を分けずに Claude Code のメインの作業で行い、原稿・サイトの品質・インフラのセキュリティの点検は、それぞれ点検専用の別の AI（サブエージェント）に任せました。たとえば、URL の末尾にスラッシュを補う転送処理に、別のドメインへ飛ばせてしまう抜け穴があったことは、インフラの点検で見つかりました。
- **未確定の情報の扱い**：料金や経歴など決まっていない情報は、画面上にも点線枠の「TODO:」として表示し、仮の文面が確定した内容に見えないようにしました。公開前にすべて解消します。
- **セキュリティの設定**：HTML にスクリプトやスタイルを直接埋め込まない作りにして、ブラウザに不正なスクリプトを実行させにくくする設定（Content Security Policy）を、ゆるめずに使えるようにしました。
- **費用**：AWS の費用は月 100 円前後と見積もっていて、ほとんどが Route 53 のホストゾーン代です（見積もりの段階の数字です。ドメインの更新料とメールの月額は別にかかります）。

# 要件定義：ひぐま開発室 Webサイト

決定済みの方針は [decisions.md](decisions.md) を正とする。本書と矛盾する場合は decisions.md を優先する。

## 1. 目的

個人事業「ひぐま開発室」の公式Webサイト。名刺代わりではなく、以下を目的とする。

- 事業内容を分かりやすく伝える
- Web制作、IT相談、AI活用支援、アプリ開発などの問い合わせを獲得する
- 事業者としての信頼感を作る
- 制作者自身の Web開発・AWS・GitHub 等の技術実績として利用する
- 将来サービスや制作物を追加できる構造にする

## 2. ブランド

- 屋号：ひぐま開発室 / 英語表記：HIGUMA LAB
- SNS/GitHub のID：`higuma_lab` または `higuma-lab`
- イメージ：
  - 小さな開発工房。個人ならではの柔軟さ
  - 技術力がある、親しみやすい、誠実
  - 「相談しやすい技術者」
- 避けるもの：過度なスタートアップ風、過度に堅苦しい企業サイト

## 3. サービス

1. Webサイト制作
2. Webサイト制作の指導・サポート
3. IT相談
4. AI活用支援
5. PC・タブレット・スマートフォン向けアプリ開発
6. アプリ開発支援

- サービスはデータとして管理し、追加・削除しやすくする。
- 特定業界向けのデザイン・コピーにしない。
- 「ITに詳しくない小規模事業者や個人事業主でも相談しやすい」ことを意識する。

## 5. トップページ

- **Hero**：屋号「ひぐま開発室」とキャッチコピー
  - コピーは以下の方向性で複数案を出し、理由を添えて提案する（独断で確定しない）
    - Web・IT・AIをもっと身近に
    - 小さな困りごとから、開発まで
    - 技術で、仕事を少しシンプルに
- **サービス紹介**：各サービスを簡潔に
- **特徴**：個人だから相談しやすい／開発経験を活かした技術支援／Webからアプリ・AIまで対応／必要なものを一緒に整理する
- **制作物・取り組み**：少数でも成立する表示（D-001）
- **プロフィール**：以下の経歴を自然な文章で紹介する
  - 医療機器向けソフトウェア開発に長年従事
  - Windowsアプリケーション開発（C/C++、C#、Python）
  - 通信・制御ソフトウェア、Web API
  - ソフトウェア開発・テスト自動化
  - 開発チームでの経験
  - ※勤務先名・製品名・機密情報は掲載しない
- **CTA**：問い合わせへの導線を明確にする

## 6. デザイン

- シンプル、モダン、技術系、親しみやすい
- 余白を十分に取る。スマートフォンで見やすい。SNS経由の訪問でも違和感がない
- ロゴ（PNG、将来SVG）を配置でき、差し替えやすい構造（D-011）
- 配色はブランドイメージとロゴを踏まえて提案する
- 避ける：過度なグラデーション、派手なアニメーション、テンプレート感の強いデザイン

## 7. 技術

- Astro + TypeScript strict、静的生成（D-002）
- 不要なクライアントJSを出さない

## 8. AWS

- 構成は D-003 のとおり（S3 + CloudFront + ACM + Route 53 + GitHub Actions OIDC、CDK）
- **AWSアカウント・DNSの実作業は行わない**。コードと手順書を完成させるまでが範囲
- 認証情報をコードに保存しない

## 9. メール・問い合わせ

- 問い合わせ先：`info@higuma-lab.jp`（設定で一元管理）
- メールサービスはサイトと分離（D-004）。初期は mailto のみ（D-005）

## 10. SEO

- 適切な title / meta description / canonical
- OGP（共通OGP画像＋ページごとの上書き）
- favicon、sitemap.xml、robots.txt
- semantic HTML、適切な見出し構造
- 構造化データ（Organization / Person / BlogPosting 等を Phase 2 で検討）
- 日本語SEOを考慮した構造（`lang="ja"` 等）
- Google Search Console への登録を想定（手順書に記載）

## 11. アクセシビリティ

- 適切なHTML要素、キーボード操作、フォーカス表示
- 十分なコントラスト（WCAG 2.2 AA 目安）
- alt属性、モバイル対応
- `prefers-reduced-motion` への配慮

## 12. パフォーマンス

- 不要なJSを減らす、画像最適化（Astro の画像最適化を利用）
- Core Web Vitals を意識、初期表示の高速化、静的生成優先

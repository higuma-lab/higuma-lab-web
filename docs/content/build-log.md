# 構築記録

ブログ1本目「このサイトの構築記録」の材料（D-016）。各フェーズの終わりに事実を追記する。
文章として整えなくてよい。判断と理由、問題と対処、数値を残す。

## 準備（2026-10-05〜10-08）

- 最初に書いた長い依頼プロンプトを、Claude Code が読み続けるルール（`CLAUDE.md`）、要件（`docs/requirements.md`）、決定ログ（`docs/decisions.md`）に分けた。
  - 理由：1つの長いプロンプトでは、会話が長くなったときに前半のルールが抜け落ちる恐れがある。
- 実装前に決定事項を選択式で洗い出した（DNS、メール、問い合わせ方式、フレームワーク、解析、公開範囲など）。
- 「実績がこのサイトとWindowsアプリだけで公開する意味があるか」を検討 → 待たずに公開し、実績ページを「制作物・取り組み」として種別ラベル付きにする方針に（D-001）。
- AI エージェントの分担を検討 → 実装は分けず、レビュー専任のサブエージェントを3つ定義（原稿、品質、インフラ）。
  - 理由：小規模サイトでは実装を分けると統一感が崩れる。別のコンテキストで点検させる方が効果が高い。

## ロゴの清書（2026-10-08）

- ChatGPT で生成した候補4案を比較。役割で使い分ける方針に：シンボル（H の形のクマの顔）とマスコット（茶色のクマのイラスト）。
  - 選定基準：SNS やブラウザのタブでは 16〜48px で表示されるため、輪郭だけで識別できるか。
- シンボルを Claude Code が SVG で描き直した（円・角丸長方形の組み合わせ、Node.js スクリプトで生成）。
  - 最初の案は H の横棒が下端にあり「U」に見えた → 横棒を上げて脚を下に伸ばし、H と読めるようにした。
  - 文字は M PLUS Rounded 1c（OFL）を opentype.js でアウトライン化。
  - SVG のサイズ：シンボル 約0.8KB、文字入りロゴ 約18KB。
- 英語表記を `HIGUMA LAB` に統一（生成画像は「Higuma lab」だった）。
- シンボルの再調整：最初の清書は「可愛くない」「目の間隔が近すぎる」との評価 → 3案を作って比較し、案1を採用。
  - 変更点：輪郭を横長の楕円に、目を元画像と同じく H の脚の近くまで離して大きく・低く、口元の下端を丸くして紺のあごを減らした。
  - 学び：幾何学的に整えるだけだと硬い印象になる。目の位置と大きさ、あごの面積が「可愛らしさ」に大きく効く。
- マスコット：ChatGPT で文字なし・背景透過の版を再生成。半透明のふち（アルファ値 235 以上を不透明に）と余白を整理。

## Phase 3：UI/UX 設計（2026-10-08）

- 配色はロゴとマスコットの画像から色を採取して決めた：紺 `#17325B`（シンボル）、茶 `#AB663C`（毛）、クリーム `#FDE6C5`（口元）。マスコットの輪郭線も `#002241` 付近の紺で、紺と茶の組み合わせに無理がないことを確認。
- コントラストを計算すると、マスコットの茶色は白背景で 4.47:1 と本文の基準（4.5:1）にわずかに届かない → 装飾専用にし、文字用に濃い茶 `#8E4F2A`（6.00:1）を別に用意。
- フォント：ロゴの丸ゴシック（M PLUS Rounded 1c）を Web フォントで見出しに使う案も検討 → 日本語フォントは分割ファイルを複数読むため数百KB 増えうる。ロゴがアウトライン化済みで統一感はロゴで出せるため、システムフォントのみを推奨。Windows では游ゴシックより BIZ UDPゴシックを優先（游ゴシックは細く薄く表示されるため）。
- Works の種別ラベル4種は色＋文字で区別（色だけに頼らない）。技術検証はブランド色と別系統の緑にした。
- 見本の HTML を1枚作り、デスクトップ・モバイルの表示をブラウザで確認してから提案した。

## Phase 4：基本実装（2026-10-08）

- `create-astro` のテンプレートは使わず、必要なファイルだけを手で作った（不要なサンプルを消す手間と混入を避けるため）。
- 依存の組み合わせで2つ詰まった：
  - TypeScript の最新は 7.0 だが、`astro check` と typescript-eslint が未対応 → 6.0 系に固定。
  - `eslint-plugin-jsx-a11y` が ESLint 10 に未対応 → `eslint-plugin-astro` が正式に対応している後継版 `eslint-plugin-jsx-a11y-x` に変更（D-031）。
  - `npm i` が `eslint-plugin-astro` の古い 1.x を黙って入れた（新しい 3.x が要求する Node 24.16 にローカルの 24.7 が満たないため）。バージョンを明示して 3.x にした。
- CSP を見越して、HTML にインラインのスクリプト・スタイルを出さない設定にした（D-032）。Astro は小さなスクリプトを既定でインライン化するため、`assetsInlineLimit: 0` で外部ファイルにした。
- JS が無効でもメニューのリンクにたどり着けるよう、`<noscript>` で外部 CSS を読み込む方式にした。
- Content Collections の既定の ID は「.」を取り除く（`privacy.en.md` → `privacyen`）ことに気づき、アプリ用ページは ID を自前で付けるようにした。
- 英語のアプリ用ページで title の末尾が日本語の屋号になっていた → 言語に応じて `HIGUMA LAB` を使うように修正。
- 確認：モバイル（375px）・デスクトップ（1280px）で表示、メニューの開閉・Esc で閉じてボタンにフォーカスが戻ること、スキップリンク。
- 数値（トップページ、仮の内容）：HTML 4.9KB、CSS 10.3KB、JS 0.4KB（メニュー開閉のみ）、ロゴ SVG 17.8KB。

- 12 ページを生成（トップ、サービス、制作物の一覧・NoteFlip の詳細、About、お問い合わせ、プライバシーポリシー、404、NoteFlip のアプリ用ページ日英4つ）。ブログは記事が0本の間は一覧ページも作らない。
- 未確定の情報は、ソースのコメントだけでなく画面にも点線枠の「TODO:」として出すようにした。公開前に消し忘れないため。
- NoteFlip の制作物ページは、NoteFlip のリポジトリの ADR・ロードマップから事実と数値を拾って書いた（UI フレームワークを試作で比べて UWP に決めた経緯、起動 0.5 秒未満、ページ送り 0.7〜8.4ms、ライブラリ読み込み 13.3 秒→0.27 秒）。
- 問題：Prettier が .astro 内の日本語の文を、式やタグの境目で改行する → ブラウザでは改行が空白として表示され「、 以下」のような余分な空白が入った。文章が中心のプライバシーポリシーは Markdown に移した。ビルド結果の HTML から「日本語の文字の間の空白」を探すスクリプトで確認した。
- 問題：YAML の折り返し記法（`>-`）で書いた説明文も、行の境目が空白になっていた → 1行で書くようにした。
- 問題：親コンポーネントの scoped CSS が、子コンポーネント（Card）のルート要素に効かない → Card に `flush` の props を足して見た目を切り替える形にした。

## Phase 6：SEO・アクセシビリティ・パフォーマンス（2026-10-09）

- OGP 共通画像（1200×630）をスクリプトで生成した。日本語のキャッチコピーは、Windows 標準の BIZ UDPゴシック（OFL）を sharp の文字描画で使った。最初は細い字で出た → プロポーショナル版の太字を指定し直した。マスコットと読点が近すぎたので、マスコットを小さくした。
- 問題：インライン化しない設定（D-032）にした結果、CSS がコンポーネントごとに約20ファイルに分かれ、1ページで十数回の読み込みになっていた → CSS を1ファイル（30.4KB）にまとめた。まとめると重なり順が変わるおそれがあるため、ブラウザで表示を確認し直した。
- 問題：Phase 4 で英語ページ用に title の作り方を変えたとき、日本語の下層ページの title が「ページ名 | ひぐま開発室（HIGUMA LAB）」になり、設計（「ページ名 | ひぐま開発室」）とずれていた → 構造化データの確認中に気づいて直した。
- 構造化データ：Organization・WebSite（全ページ）、BreadcrumbList（パンくずと同じデータから）、BlogPosting（記事）。本名・住所を出さないため、Person と LocalBusiness は使わない。
- site-auditor の点検：要修正0・推奨2・任意4。404 に存在しない URL の canonical が出ていた、英語ページの OGP 画像の説明が日本語だった、など → 修正した。
- 数値：dist 全体 496KB、HTML 5〜13KB、CSS 30.4KB（1ファイル）、JS 433B、最大の画像は OGP 画像 101KB、マスコットの webp は最大 39KB。

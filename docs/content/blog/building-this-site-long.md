## 進め方：ルールを書いて、フェーズごとに止める

最初は1つの長い依頼文を書きましたが、会話が長くなると前半の指示が抜け落ちるおそれがあります。そこで、依頼文を次の3つに分けました。

- **作業ルール**（`CLAUDE.md`）：毎回読み込まれる、変わりにくいルール。「架空の実績を作らない」「未確定の情報は `TODO:` を付けた仮の内容にとどめる」「AWS の実環境には触らない」など
- **要件**（`docs/requirements.md`）
- **決定事項**（`docs/decisions.md`）：決めたことと理由を番号付きで残すログ。最終的に 36 件になりました

作業は9つのフェーズに分け、設計・UI 設計・テスト・インフラの終わりでは必ず止まって、私が確認してから次に進むようにしました。各フェーズの終わりには、判断と理由、問題と対処、数値を記録してもらい、この記事はその記録から書いています。

点検は、実装とは別の「レビュー専任のサブエージェント」に任せました。原稿の事実性・個人情報を見る `content-reviewer`、ビルド結果の品質を見る `site-auditor`、インフラのセキュリティを見る `infra-reviewer` の3つです。小さなサイトで実装を複数の AI に分担させると統一感が崩れやすいため、実装は役割を分けずにメインの作業で行い、点検だけを別のコンテキストの AI に任せる形にしました（作業のセッション自体は、確認のたびに切り替えています）。

## 設計で決めたこと

- **フレームワーク**：Astro、Next.js（静的出力）、Eleventy・Hugo を比べて Astro にしました。JavaScript を出さないのが既定で、Markdown のコンテンツに型付きのスキーマを付けられるためです。
- **DNS**：ドメインはお名前.com で取得しましたが、DNS は Route 53 にしました。ドメイン直下（`higuma-lab.jp`）を CloudFront に向けるためです。
- **実績が少ない状態での公開**：実績がこのサイトと公開予定のアプリだけでも、待たずに公開することにしました。そのかわり、制作物には「自社プロダクト」「サンプル制作」「技術検証」「お客様案件」の種別ラベルを付け、お客様の案件と混同されないようにしています。
- **コミットのメールアドレス**：リポジトリは公開する予定のため、git の設定を GitHub の noreply アドレスに変えました。最初のコミットの前に気づけたので、履歴に個人のアドレスは残っていません。

## ロゴとデザイン

ロゴは、ChatGPT で生成した候補から「H の形でクマの顔を作り、口元に `</>`」の案を選び、Claude Code が SVG で描き直しました。円と角丸の長方形を組み合わせて Node.js のスクリプトで生成しています。

- 最初の清書は、H の横棒が下にあって「U」に見えたため、横棒を上げて脚を伸ばしました。
- 次の版は「可愛くない」という評価でした。3案を並べて比べ、輪郭を横長の楕円に、目を大きく離して低く、あごの面積を減らした案にしました。幾何学的に整えるだけでは硬くなり、目の位置とあごの面積が印象を大きく変えることが分かりました。

配色は、ロゴとマスコットの画像から色を拾って決めました。マスコットの茶色は白い背景で 4.47:1 と、本文の文字に求められるコントラスト（4.5:1）にわずかに届かなかったため、装飾専用にして、文字には濃い茶色を別に用意しています。フォントは Web フォントを読み込まず、OS に入っているものだけを使っています。

## 詰まったところ

- **依存パッケージの組み合わせ**：TypeScript の最新版（7.0）に、型チェックと ESLint の道具がまだ対応していませんでした。6.0 系に固定し、アクセシビリティの ESLint プラグインも ESLint 10 に対応した後継版に替えました。
- **日本語の文中の余分な空白**：Prettier が `.astro` ファイルの中の日本語の文を、タグの境目で改行していました。ブラウザは改行を空白として表示するため、「、 以下」のような空白が入っていました。文章が中心のページは Markdown に移し、ビルド結果から「日本語の文字の間の空白」を探すスクリプトで確かめました。
- **CSS が約 20 ファイルに分かれる**：セキュリティの設定（CSP）を厳しくするため、HTML にスクリプトやスタイルを直接埋め込まない設定にしたところ、CSS がコンポーネントごとに約 20 ファイルに分かれました。1ファイル（約 30KB）にまとめました。
- **AWS のリージョンが分かれる**：CloudFront 用の証明書はバージニア北部（us-east-1）にしか置けず、東京リージョンのサイトと分かれます。CDK のリージョンをまたぐ参照の機能で受け渡しました。
- **CI で初めて分かった問題**：Windows で作ったインフラ側の lock ファイルに、Linux 用のバイナリの記載が抜けていて、GitHub Actions の `npm ci` が失敗しました。手元では再現しない種類の問題で、CI を Linux で動かしていたことで見つかりました。
